# 维护者指南

本指南用于保护自学坊官方仓库和官方网站的质量。许可证允许社区 Fork 和改编项目，但只有通过本仓库审核并合并到 `main` 的内容才代表官方版本。

## 一、首次配置仓库

在 GitHub 的 `Settings → Rules → Rulesets` 中为默认分支 `main` 创建并启用规则集：

- Require a pull request before merging；
- Required approvals：至少 1；
- Require review from Code Owners；
- Dismiss stale pull request approvals when new commits are pushed；
- Require conversation resolution before merging；
- Require status checks to pass；
- Block force pushes；
- Restrict deletions。

将 `Quality checks / validate` 设置为必需状态检查。`Link check / links` 建议先观察数周，完善反爬白名单后再设为必需检查，避免第三方网站的临时故障阻塞所有贡献。

仓库所有者可以保留紧急绕过权限，但只应用于安全修复或部署故障，并在事后补充说明。

## 二、建议标签

Issue 表单会尝试使用以下标签，请在仓库中提前创建：

| 标签 | 用途 |
| --- | --- |
| `资源推荐` | 新课程、教材、论文和工具 |
| `失效链接` | 无法访问或内容迁移 |
| `内容修正` | 描述、难度、前置或关系错误 |
| `学科规划` | 新学科和课程结构 |
| `待审核` | 等待编辑判断 |
| `待核查` | 需要人工验证事实或链接 |
| `需要讨论` | 合并前需要形成共识 |
| `good first issue` | 范围清楚、适合首次贡献 |
| `不予收录` | 不符合范围或质量标准 |

## 三、Pull Request 审核顺序

1. **范围**：是否只解决一个问题，是否与项目目标一致；
2. **版权**：链接是否合法，是否复制了无权发布的内容；
3. **事实**：课程名称、学校、难度、前置和描述是否准确；
4. **质量**：是否比现有资源更完整、公开或适合自学；
5. **结构**：课程顺序和知识图谱关系是否有依据；
6. **体验**：桌面端、移动端、导航和无障碍是否正常；
7. **自动检查**：Lint、构建和链接检查是否通过。

审核内容时不要只看链接是否返回成功状态；还要确认页面标题、发布者和实际教学内容与网站描述一致。对 403、429、超时或地区限制进行人工浏览器复核。

## 四、权限管理

- 新贡献者默认通过 Fork 和 Pull Request 参与；
- 能稳定分类 Issue 的成员可授予 Triage 权限；
- 只有持续贡献并理解收录标准的维护者才授予 Write 权限；
- 即使获得 Write 权限，也继续通过受保护的 Pull Request 合并；
- 学科负责人通过 `.github/CODEOWNERS` 按文件指定，不给予整个仓库的无条件控制权。

## 五、合并与发布

- 推荐使用 Squash merge，并写清最终提交说明；
- 合并前确认所有讨论已解决且最新提交经过审核；
- GitHub Pages 只从 `main` 的部署工作流发布；
- 发布失败时优先回滚单个 PR，不重写共享分支历史；
- 对重要内容调整，在 PR 中保留来源和决策理由。

## 六、定期维护

- 每周查看自动链接检查结果；
- 每月处理长期无人回应的 Issue；
- 每季度抽查重点学科的课程内容和前置关系；
- 每半年复核维护者权限、CODEOWNERS 和收录标准；
- 对反复失效或转为付费的资源寻找稳定的官方替代。

维护的目标不是收录最多资源，而是让每一条路径都可信、清晰并真正适合自学。
